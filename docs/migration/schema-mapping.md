# Azure SQL ↔ Supabase PostgreSQL Schema Mapping

| Azure SQL (EF) | PostgreSQL (Supabase) | Notes |
|----------------|----------------------|-------|
| `int` IDENTITY | `INTEGER GENERATED BY DEFAULT AS IDENTITY` | Preserve IDs during data migration |
| `nvarchar(n)` | `VARCHAR(n)` | Same max lengths |
| `datetime2` | `TIMESTAMPTZ` | UTC via `timezone('utc', now())` defaults |
| `bit` | `BOOLEAN` | |
| `decimal(18,6)` | `NUMERIC(18,6)` | Map coordinates |
| `GETUTCDATE()` | `timezone('utc', now())` | API uses `DatabaseProviderKind.UtcNowSql` |
| Filtered unique index `[Col] IS NOT NULL` | `WHERE "Col" IS NOT NULL` | Email/password reset tokens |
| `Users.PasswordHash` NOT NULL | nullable | OAuth users have no password hash |

## Tables (8)

1. `Users` — auth credentials, OAuth tokens, roles
2. `Runners` — FK → `Users`
3. `Cases` — FK → `Runners`, `Users` (reporter)
4. `Devices` — FK → `Users`
5. `TopicSubscriptions` — FK → `Users`
6. `Notifications` — FK → `Users`
7. `DataDeletionRequests` — FK → `Users`
8. `AccountDeletionRequests` — FK → `Users`

## Migration schemas

| Schema | Purpose |
|--------|---------|
| `public` | Application tables + public views |
| `migration` | Identity map, run checkpoints, blob map |

## EF Core behavior

- `DATABASE_PROVIDER=SqlServer` — EF migrations in `Migrations/SqlServer/`, auto-migrate on startup
- `DATABASE_PROVIDER=Postgres` — schema from `supabase/migrations/`, **no** EF auto-migrate

## Sequence reset after data copy

The data migration tool calls `setval` on each table's identity sequence after insert to avoid PK collisions on new rows.
